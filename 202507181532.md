A wide transformation is 
- an operation
- that requires a data shuffle across the cluster
- introduce dependencies between partitions
	- an output partition depends on data that might be scattered across many input partition

So data needs 
- to be moved over the network 
- between different physical node 
- to bring together all the necessary information for a given output partition.

They are generally **more resource-intensive and can significantly impact the performance** of Spark applications due to the overhead of data shuffling

---

- **`groupByKey()`**: Groups elements by key, collecting all values for each key. This inherently requires all values for a given key to be in the same partition.
    
- **`reduceByKey()`**: Aggregates values for each key using a reduce function. While it's often more optimized than `groupByKey()` (as it can perform local aggregation before the shuffle), it still requires a shuffle to bring all values for a key together.
    
- **`join()`**: Merges two RDDs or DataFrames based on a common key. To find matching keys, data from both datasets usually needs to be shuffled so that matching keys end up in the same partition.
    
- **`distinct()`**: Returns a new RDD or DataFrame containing only the unique elements. Determining uniqueness across the entire dataset requires shuffling to compare elements from different partitions.
    
- **`sortByKey()` / `orderBy()`**: Sorting an entire dataset requires all data to be brought into a sorted order, which typically involves shuffling.
    
- **`repartition()`**: Explicitly changes the number of partitions of an RDD or DataFrame, often involving a full shuffle of the data.
