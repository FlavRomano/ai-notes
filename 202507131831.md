RDD stands for **Resilient Distributed Datasets**. It is the data that we'll work with, with a peculiar feature:
> If a node $u$ fails, $u$ partitions can be recovered and recreated.

Is an abstraction that makes Spark fault resistant.

![[Pasted image 20250713183449.png]]

Spark uses a principle called "lazy evaluation" (like java collection stream's), a sequence of manipulation on some RDD 
- doesn't create every time a new RDD
- doesn't get executed in order
	- at line 1, we don't load the dataset directly
	- instead, Spark adds it to the execution plan
- at the end spark execute the execution plan.
