**Data shuffling** 
- is the process of redistributing data across the nodes in a cluster. 
- It's Spark's way of reorganizing data so that elements with the same key are brought together onto the same partition
- enabling operations that require global aggregation or coordination.
	- wide-transformation

When an operation that need shuffling occurs:
- **Map Phase (Write):** 
	- Each Spark executor processes its local partitions. 
	- For data that needs to be shuffled, it determines which "target" partition that data belongs to based on a partitioning key (e.g., the key in a `(key, value)` pair). 
	- It then writes these intermediate results to local disk as "shuffle files."
    
- **Shuffle Phase (Transfer):** 
	- Once the map tasks are complete
		- the executors exchange these shuffle files over the network. 
	- Each executor pulls the data that is destined for its own partitions from the shuffle files written by other executors.
    
- **Reduce Phase (Read & Process):** 
	- The executor then reads the incoming shuffled data, 
	- potentially sorts it
	- and proceeds with the next stage of the computation

When a shuffle happens, Spark creates a new Stage.
