A **narrow transformation** in Spark 
- is an operation 
- that doesn't require any shuffling of data across partition.
- and that can happen independently within each partition.

Technically speaking
- each partition of the parent RDD
- contributes to at most one partition of the child RDD

So all the necessary data for a given output partition is already present on the same physical node.

 They are **much faster and more efficient** than wide transformations:
- They avoid costly data shuffling over the network
- Spark optimizes the narrow transformations by pipelining them
	- it can execute a series of narrow transformations on a partition
	- without writing intermediate results to disk

---

Examples of narrow transformations include:
- **`map()`**: Applies a function to each element independently.
- **`filter()`**: Selects elements that satisfy a predicate.
- **`union()`**: Combines two RDDs without repartitioning.
- **`distinct()`** (when applied to an RDD that already has unique keys within partitions)
